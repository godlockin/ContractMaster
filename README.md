## 给合同审核多一层复核

合同审核需要逐条读，也需要把定义、价款、履行、例外和责任放在一起看。对方删去一个“每年”，调整一个“且”，或者更换一份附件，都可能改变交易安排。

**契衡帮助你整理疑点、追踪修改、准备协商意见。** 它把法律、争议解决、财务、业务、合规及文字逻辑等审查视角组织成可复核的工作流程，输出原文位置、影响分析、修改方向和待确认事项，供律师、法务及业务负责人裁定。

契衡以大模型 Skills 技能包提供，可加载到支持技能、本地文件与脚本执行的大模型工作环境。你用自然语言说明任务，由助手完成材料整理和审核流程；无需自己编写程序或配置专家名单。

## 适合用在什么场景

| 你的工作 | 契衡可以协助 |
|---|---|
| 合同律师审阅初稿、准备谈判意见 | 定位问题条款，关联上下文，整理修改方向与待核事实 |
| 企业法务审核对方返回稿 | 对比原稿与返回稿，逐项解释权利义务和履约风险变化 |
| 法务配合采购、销售、财务审查 | 连贯核对价款、税费、交付、验收、付款及违约安排 |
| 同一交易经历多轮谈判 | 按案例保存合同、附件、版本、比较记录及审核报告 |
| 签署前核对选定稿件 | 比较指定文本版本，提示新增改动；签章、图片及复杂版面另行核对 |

默认围绕中国大陆法域开展审查。具体结论结合合同类型、我方立场、交易背景和适用规则判断。

## 特别关注：小改动，大影响

| 原稿 → 修改稿 | 需要复核的变化 |
|---|---|
| 未来三年 **300万/年** → 未来三年 **300万** | 若从每年支付变为三年总额，900万可能变为300万，差额600万；还须核对总价、分期及税费条款 |
| **应当**付款 → **可以**付款 | 义务是否被改为选择权，是否影响付款请求基础 |
| **累计**不超过100万元 → **每次**不超过100万元 | 责任上限的计算范围是否变化 |
| **收到**通知起10个**工作日** → **发出**通知起10个**自然日** | 起算时点及期限是否同时变化 |
| 条件A **且** 条件B → 条件A **或** 条件B | 权利行使或责任触发条件是否放宽 |

这些是复核提示，不能仅凭词语变化认定法律效果。没有触发提示的修改，也须逐项审核，并关联未修改条款与附件。

## 你会收到什么

- **问题清单**：原文位置、触发条件、可能影响、修改方向与待确认事实。
- **修改对比**：两版文字、增删改位置、各项修改的审查意见及未决事项。
- **全文关联意见**：定义、例外、正文与附件、金额与期限之间的冲突或缺口。
- **依据与限制**：法源核验状态、材料缺失、尚未解决的分歧，明确哪些判断仍需复核。
- **可追溯记录**：报告绑定具体合同版本与合同组快照，便于回看历轮材料。

想先看交付形式，可直接打开[原创采购合同审查报告](examples/purchase/REPORT.md)，或查看[六个原创案例的处理过程](docs/WALKTHROUGH.md)。样例包含历史试审意见，用于展示形式，不代表你的合同已经接受审核。

## 如何开始使用

### 1. 加载技能包

取得项目后，将 `contract-review-cn/` 文件夹导入所用大模型工作环境的 Skills 管理功能；支持直接读取技能文件的环境，也可加载其中的 `SKILL.md`。具体加载方式以该环境的说明为准，详见[加载与环境指南](docs/GETTING-STARTED.md)。

### 2. 告诉助手材料、立场和关注点

审核新合同：

```text
审核工作目录里的采购合同和质量附件。
我方是采购方，重点关注验收、付款、质量责任和退出安排。
请在当前工作目录建立案例，保存这次审核记录。
```

审核对方修改：

```text
这是我方V1和对方返回的V2，请归入同一案例。
逐项审核修改，尤其关注金额、计价周期、责任上限和例外条件，
并检查修改与其他条款、附件是否冲突。
```

继续已有案例：

```text
在我指定的合同目录继续维护案例C001。
加入本轮返回稿，并分别与上一轮版本、我方初稿比较。
```

### 3. 核对材料，再查看意见

助手先探测并优先调用本地敏感信息模型；模型不可用时自动回退本地规则。你需要核对文字是否完整、附件是否齐全、敏感内容是否妥善处理；确认后才进入模型审核。后续只需补充影响判断的必要事实，审阅报告并决定如何修改。

**原件和敏感映射保留本地；经复核发布的脱敏内容会交给所用模型处理。** 使用者应按自身材料保密要求选择和配置工作环境。

首次使用可在案例目录建立本地隐私策略，填入公司、人名别名、项目代号、内部报价、技术秘密及金额发布规则：

```bash
python3 contract-review-cn/scripts/privacy_config.py init --root /你的案例目录
python3 contract-review-cn/scripts/privacy_config.py check --config /你的案例目录/privacy-policy.json
```

策略文件、原文和映射不会上传；规则降级时也必须完成本地复核，只有复核后的公开脱敏包才进入模型审核。

## 合同往返多轮，也能理清版本

案例库默认位于用户工作目录下的 `contract-cases/`，也可指定其他目录。实际合同材料与技能源码分开保存。

```text
案例 C001
├── 合同与附件：各自保留 V1、V2、V3 及前序关系
├── 合同组快照：固定每一轮正文与附件的具体版本
└── 审核记录：保存比较基准、审核输入与各版报告
```

附件按稳定编号配对，减少漏附件、错配及新旧版本混用；可比较任意两份同组快照。已有版本拒绝覆盖，内容摘要用于检查原件与审核记录是否一致。最新收到的版本不会自动视为已批准稿。

完整目录与操作见[案例管理说明](contract-review-cn/references/case-management.md)。

## 审核方式与适用边界

流程安排两组审查角色：一组从多背景正向审核，另一组独立逆向查漏；首轮独立审阅，随后双向质询与全文回归。实际角色调用由所用大模型工作环境执行；无法完成的步骤须明确记录，不能用角色名称冒充真实独立审核。

| 材料格式 | 当前处理方式 |
|---|---|
| DOCX、TXT、Markdown | 本地提取文字，再核对完整性 |
| 有文字层的 PDF | 按需安装文字提取依赖 |
| 旧版 DOC、RTF、ODT | 先用本地文档软件转换 |
| 扫描 PDF、照片 | 先本地文字识别并核对 |
| 复杂修订、格式、签章、图片 | 仍需本地可视核对，文本比较不能覆盖全部变化 |

契衡定位为**专业人员主导的合同审核辅助工具**。未决问题、材料缺口和未核验依据保留在报告中；结构校验通过不代表穷尽法律风险，也不代表合同可以签署。目前尚未完成独立律师金标准评测。

## 配置与维护

以下内容供环境配置人员及项目维护者使用，日常审核无需手动执行这些命令。

Python 3.10+；TXT/MD 与基础 DOCX 解析使用标准库。PDF 文字提取按需安装固定依赖，详见[环境指南](docs/GETTING-STARTED.md)。

无需模型调用的本地演示：

```bash
python3 demo.py
```

演示只处理固定原创样本：实际执行提取、脱敏及引文校验，并回放已保存的3项历史意见；不会新运行模型审核，也不接受真实合同作为演示输入。

统一工程验证：

```bash
.venv/bin/python scripts/verify.py
```

当前已验证环境：Python 3.14.7、pypdf 6.18.0。**94项测试通过，零跳过**，另有6个合成案例流程检查通过。测试覆盖技能、案例管理、复核工具、隐私模型实验工具及回归检查；这些数字不表示法律准确率或敏感信息识别合格。持续集成配置覆盖 Python 3.10/3.14，实际执行结果以任务记录为准。
