# 审查问题修复记录

- F1：DOCX XML 错误转换为静态错误码，记录 input gap，继续处理有效文件。
- F2：报告所有不可信文本字段统一 Markdown 转义，换行显示为可见标记；保留脱敏 token 原字节，支持本地身份恢复。
- F3：普通校验与深度校验共享问题解决声明检查。无深度数据时，未知法源/证据引用保持待确认，不展示已解决。
- F4：run 存在 active-plan 时，省略 `--plan` 报 ACTIVE_PLAN_REQUIRED；未激活计划的历史 run 仍兼容。
- F5：交叉质询的 finding 必须属于指定报告 SHA256 对应文件及合同。
- F6：语料恢复检查本地材料及摘要，不再只依赖历史 DOWNLOADED；缺失时重建，路径改为相对路径。恢复原件若与历史摘要不符则失败，要求显式更新语料版本。使用注入的离线下载器验证八份语料恢复与再次运行不重复下载。
- O1：重叠匹配使用坐标压缩和 Fenwick 前缀计数，选择阶段从 O(M²) 改为 O(M log M)。维持最长优先和稳定排序语义；150 组随机合成输入通过旧算法差分对照及脱敏往返校验。

本机 8,000 次手机号匹配：修复前约 0.5845 秒，修复后约 0.0178 秒，约 33 倍加速。单轮合成测量，不代表所有文档负载。

验证：技能 33 项、人工复核包 6 项、演示及审查回归 8 项，共 47 项；46 通过，1 因可选 pypdf 未安装跳过。另执行 6 个合成案例流程验收及审查回归脚本。未联网下载真实语料，未运行真实模型或律师质量评测。
