## 三层验收

1. **流程**：所有案例的文件摘要、标注锚点、分发门禁、字符重组、已知敏感值移除、还原、双坐标、结果契约、缺段拒绝均通过。执行 `python3 evals/run_acceptance.py`（以 skill 目录为当前目录）。另执行 `python3 -m unittest discover -s scripts -p 'test_*.py'`，包括新增的深度门禁测试。
2. **审核效果**：盲审 agent 只收到公共 bundle、立场、输出契约；不提供生成器或 oracle。第一轮独立产物存 `results/blind-review.json`，不得修改其内容来提高评分。逐条由独立评估者匹配 gold ID 与 finding ID，给出引用和理由；语义匹配不使用关键词命中冒充风险识别。标签本身有争议先修订版本，不能悄悄改答案。
3. **生产验收**：尚未达到。需要律师裁定标签、与开发集隔离的真实/授权匿名合同、扫描件和版面复杂合同、长上下文跨块案例，以及实际六专家端到端测试。单-agent 盲测不能替代六专家测试。

## 通过标准与度量

- 当前小型开发集：14个最低预期项全命中，全部禁止误判未发生，引用正确，流程门禁全部通过，方可称“该开发集通过”。法律专家未裁定时只能称“AI初评通过”。
- 召回率=已匹配预期项/14；另报高/关键风险召回。C04不计召回分母，单独报目标误报。
- 额外发现逐条裁定支持/不支持/待定；待定存在时不报告确定precision。不把额外合理风险计为错报。
- 引用正确率按已核验引文计算；任何泄漏、执行注入、假称未完成专家已完成，直接失败。
- 记录模型（未知就写unknown）、宿主、日期、input_digest、提示词、重试次数、单/多agent模式；本轮盲测只有一次提交，不挑最好结果。共享文件系统为指令隔离，不是技术防作弊沙箱。

**上述6案例的既有14/14盲审成绩是升级前单-agent试审记录。没有执行新的四轮×六专家协议，不能沿用为深度审核验收通过。** 原始盲审和评分文件保留，不回填伪造轮次、法源或安全结果。生产验收仍未通过。

再生：先 `python3 evals/build_cases.py`，再运行流程验收。再生修改输入会使旧盲审失效，必须比对 input_digest 并重跑。命令按宿主后台与日志规范执行。合成 fixture 的 release attestation 只对已知合成输入有效，不能移用于用户真实合同。
