# 输入格式与按需依赖引导

## 原则

不在首次使用安装全部依赖。先探测当前解释器及本次文件；只在实际需要时建议安装。用户拒绝、无权限或安装失败均不循环劝装，不执行sudo、不全局升级环境。已安装在其他解释器中的库不等于agent当前解释器可用。

| 输入 | 内置处理 | 可选能力 / 替代路径 |
|---|---|---|
| UTF-8 TXT / Markdown | Python标准库 | 无额外库 |
| Word .docx | Python标准库读取正文、表格、页眉页脚、脚注等 | 修订、图片、隐藏内容和版面需本地核对；不用安装python-docx即可基础提取 |
| PDF文字层 | 可选pypdf | 缺失时建议安装；或用用户已有本地软件导出DOCX/TXT |
| PDF扫描/混合页 | 不保证可提取 | 本地OCR后再检查；pypdf不是OCR，安装后也不能承诺处理扫描页 |
| Word .doc、RTF、ODT | 不能直接提取 | 用户已有Word/LibreOffice等本地软件另存DOCX/TXT，保留原件与转换关系 |
| PNG/JPG照片 | 不能直接提取 | 本地OCR/人工转录及核对；不要擅自上传在线转换服务 |
| 加密PDF | 当前拒绝 | 用户有权限时本地解锁副本，再处理；不在对话索取密码 |
| 附件上传 | 宿主提供的本地路径 | 按文件格式处理；没有可读本地文件时请提供文件 |

Word支持指DOCX直接支持，不能宣传所有Word格式原生支持。仅改文件扩展名不是转换。

## 引导阶段

1. 在本地用实际将执行处理的Python运行 `scripts/pipeline.py doctor --input <文件> ...`。输出仅文件序号、已知格式、依赖状态和动作，不读取正文；原路径由主agent在本地与序号对应。
2. 可直接处理的先进行prepare。doctor的READY只表示格式及依赖就绪，不证明文件可解析、未加密、含文字或内容完整。
3. 缺PDF库时，说明“该PDF暂不能处理；其他支持格式可继续”，提供安装或本地导出的选择。用户已明确拒绝则直接使用替代路径，不再询问安装。
4. 用户选择安装时，在其允许的项目虚拟环境执行：`<当前解释器> -m venv .venv`，然后 `<venv解释器> -m pip install pypdf`。使用参数数组或正确引用路径，不拼接合同文字。失败记录简短原因，继续其余文件；不自行sudo或换全局环境。
5. 安装成功后用该解释器再运行doctor及实际提取，不以pip退出0代替处理成功。Python自身不可用时，说明本地处理暂不可执行；用户仍可浏览示例和既有报告，但不能冒称真实合同已处理。

## 混合输入与补齐

prepare逐文件提取；缺依赖、文件不存在、格式不支持或可识别的解析失败只影响对应文件。成功文件进入候选包，未处理文件序号和原因进入 `input_gaps`；原路径只记录在 `private/input-errors.json`。所有输入失败则返回非零，不生成可发布的空包。

只要有input_gaps，深度状态不能完整通过。主合同或关键附件缺失时，剩余文件可以做有限分析，但必须说明对关系判断的限制。不能为通过验收删掉input_gaps。

用户补齐依赖或转换文件后，建立新运行目录并提交完整输入清单；重新提取、核对、发布和审查。不得把补齐文件直接混入已冻结包或沿用旧输入摘要。只读原件、转换后的文件也保持本地隐私边界。
