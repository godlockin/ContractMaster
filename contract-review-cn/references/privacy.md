# 隐私与脱敏门禁

## 本地边界

每次审核使用全新、非同步目录，目录 0700、文件 0600。脚本拒绝复用运行目录；映射明文只存本地，**文件权限不等于加密**。设备加密/受控磁盘由用户环境提供。不要把任务目录放入公共仓库、网盘或共享 /tmp；生产建议 `~/.local/share/contract-review-cn/runs/<随机编号>`。不要在云工具中读取原件或 private；本地查看也不能用会把文件内容返回模型的工具。

private 存原文快照、mapping.json、candidate.json、提取清单；public 仅包含经复核的脱敏包；reports 存脱敏结果。映射按运行隔离，相同字面值同一标记，不同字面值分别标记；不同别名关系由用户补充脱敏语义信息，不能猜测实体相同。替换采用最长优先、非重叠策略，保存原文及脱敏文本双坐标；offset 为 Python Unicode code point、左闭右开，不是字节或 UTF-16 单元。

## 识别范围

脚本规则：大陆身份证、手机、邮箱、统一社会信用代码、疑似长账号。规则有漏报和误报；公司/人名/地址/项目代号/内部报价/技术秘密通过本地实体词典补充。字典格式：

```json
{"entities": [{"value": "本地真实主体名", "type": "ORG"}, {"value": "本地项目代号", "type": "PROJECT"}]}
```

真实词典不要粘贴给 agent。在本地编辑器维护；`prepare --entities <词典路径>`。当数字账号识别误吞合法金额时，不能直接 release，应调整输入/规则或局部词典后重新复核。

金额、百分比、日期、币种、甲乙方角色、履行关系默认保留，便于计算和判断。它们也可能是商业秘密，release 前由用户明确是否可分发；需要遮盖时加入实体词典。若遮盖会阻断判断，记录“需本地核算”及约束（如金额关系是否一致）；禁止编造替代数字继续算。脱敏主体会使资质/关联方/受制裁主体判断不可执行，报告必须列明。

## 两项复核缺一不可

1. 提取核对：用户在本地逐页对照原件，检查页数、表格、签署栏、附件、图片文字、脚注、修订、隐藏文本、批注、阅读顺序；提取失败不能当“无条款”。
2. 隐私核对：用户或可信离线工具检查 candidate 内所有文本字段及文件标签，确认没有真实身份、秘密、敏感上下文残留；可保留数值范围明确。人审完成以后告知主 agent “本次提取及脱敏已复核”。主 agent 才执行 release 两项 attest。

不让云 agent 充当“原文隐私复核员”。规则扫描无命中不等于完成上述两项确认。若当前用户只是授权构建 skill，不能把构建授权用于将来任何合同的 release。

## 保留与恢复

保留周期按用户要求；不自动删除唯一映射。所有导出采用新文件，禁止覆盖源合同。restore 只还原精确标记、单次替换，不递归解释被还原值。用户要求清理时先明确要删除的运行编号，原始上传文件另行保留。失败日志不包含异常对象文本、合同内容、实体值、映射或完整堆栈。
