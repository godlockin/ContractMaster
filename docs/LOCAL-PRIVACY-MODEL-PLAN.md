# 契衡：本地敏感信息模型与私密处理实施计划

计划日期：2026-09-14。本文保留初版规划与估算；本地环境、数据准备和四轮微调已执行，候选尚未通过验收，隔离部署未完成。实测与差距见[实验报告](PRIVACY-MODEL-EXPERIMENT-2026-09-14.md)。以当前技能包为基础增强，不另建云服务。

## 1. 结论与目标

现有机器足够开展本地敏感信息识别、量化LoRA微调和单用户推理，不建议现在采购显卡或云算力。先以规则＋现成小模型建立基线，有明确差距再训练。

目标分为两条，分别验收：

1. **识别能力**：从合同中定位身份、联系信息及业务敏感片段，确定性替换并保留映射，不改写合同含义。
2. **私密处理边界**：处理原件的环境不能向外发送合同、映射、训练样本或内容日志。若要求审核内容也不外发，审核推理必须留在本地，不能自动降级调用远端模型。

本计划不承诺“任何情况下除本人外绝无第二人可见”。本机管理员、恶意软件、物理访问、备份和密钥泄露均需另行控制。断网和隔离减少外发路径；识别器解决漏检问题，两者不能互相替代。

## 3. 模型与开源组件选择

| 组件 | 推荐方案 | 用途及取舍 |
|---|---|---|
| 确定性识别 | 现有Python规则＋实体词典 | 处理证件、电话、邮箱、账号；补格式校验、分隔符与断行场景 |
| 首选语义识别 | Qwen3-1.7B | 中文指令模型，低成本基线；关闭思考模式，限制结构化输出 |
| 对照模型 | Qwen3-4B | 检查更大模型是否确实减少上下文漏检，再决定部署哪一档 |
| 微调/推理 | MLX-LM | 苹果芯片本地LoRA、量化LoRA和推理；独立环境固定版本 |
| 可选便携推理 | llama.cpp＋GGUF | 后续需要多平台分发时再适配，不在首轮同时维护两套后端 |
| 可选实体识别支线 | 许可明确的中文编码器＋ONNX Runtime | 若延迟/功耗成为瓶颈再试，不预先叠加第三个模型 |
| 数据与评测 | 本地JSONL、Python校验、简单本地复核页 | 不要求外部标注平台账号，不上传真实样本 |

核验时Qwen3-1.7B与4B官方模型卡标注Apache 2.0；MLX-LM、llama.cpp、ONNX Runtime仓库许可证为MIT。实际采用版本仍记录LICENSE、NOTICE、版本和文件摘要。第三方转换权重不代替官方权重来源核对。

模型下载优先使用当前网络可访问的官方发布渠道。镜像须核对发布者、许可与权重来源；不可达时调整下载渠道或离线导入，不承诺所有外部托管站点在不同网络下可用。运行模式不依赖外网账号。

不从零预训练，也不首选全参数微调。MLX的量化LoRA按其实现使用，不照搬其他GPU生态的安装脚本或内存估算。

## 4. 硬件、文件和时间预算

以下仅用于容量规划：单进程、短片段、4bit基础权重、低秩适配器、小批量；内存随序列、适配层数、优化器及实现变化。系统和日常应用预留约10～12GB，不修改系统内存限制强行塞入模型。

| 规模 | 4bit权重文件参考 | 推理进程内存参考 | 量化LoRA内存参考 | 本机建议 |
|---|---|---|---|---|
| 1.7B | 约1～1.5GB | 约3～6GB | 约8～16GB | 首选 |
| 4B | 约2.5～3.5GB | 约5～10GB | 约14～28GB | 对照与备选 |
| 7～8B | 约4.5～6GB | 约8～16GB | 约24～40GB或更高 | 不纳入首轮；只有收益明确时试验 |

原始半精度权重约按参数数×2字节估算：1.7B约3.4GB、4B约8GB，另加词表及元数据。适配器通常几十至几百MB，也可能更多；不能只交付适配器却遗漏基础模型。保留原始权重、量化副本和少量检查点，先规划**50～100GB工作空间**；禁止自动无限保留检查点。

### 试跑参数与测量

- 初始输入长度512～1024 tokens；必要时提升到2048。按段落/表格行切分，重叠窗口保留跨边界实体；不能把截断当作无敏感信息。
- 批量1、梯度累积、低秩适配器；按实测选择适配层数与梯度检查点。
- 测量冷启动、输入处理速度、完整片段延迟P50/P95、峰值进程内存、系统内存压力、swap增长、输出格式失败率。
- 先跑100～300训练步。持续内存压力或明显swap增长时停止并降低负载；不在机器承担其他重任务时比较速度。
- 初步训练工时预算：1.7B每轮约2～12小时，4B约4～24小时，均以约5千～1万条短样本、1～2个epoch为假设。若试跑慢于预算，更新计划，不把估算写成实测成绩。
- 校准公式：优化步数约为 `ceil(样本数 / 有效批量) × epoch`；总时长按实测每步时间加验证、保存及预处理时间计算，并核对梯度累积计数方式。

不预报每份合同固定几秒完成：长度、表格、窗口重叠与输出实体数都会改变时延。第一阶段测量后再确定业务时延目标。

| 数据源 | 用途 | 处理规则 |
|---|---|---|
| OpenPII 1.5M的中文子集 | 通用隐私实体样本 | 页面声明含中文、合成个人信息及CC BY 4.0；元数据license为other、license_name为cc-by-4.0，未发现独立许可证文件。留存许可页面与具体revision；许可解释仍有疑问时先不用于对外发布模型 |
| CLUENER2020 | 姓名、公司、地址等中文实体对照 | 10,748条训练记录、新闻领域；本次未确认明确数据许可，不进入默认产品训练包，待授权确认 |
| 原创合成中文合同 | 主训练域：项目代号、报价、技术参数、别名、合同组合关系 | 生成与标注脚本保存在仓库；虚构身份，人工核查标注及业务合理性 |
| 经用户批准的真实合同 | 后期受控验证或有针对性的补充训练 | 只能在本地受控环境处理；先确认处理权利、留存和标注权限，不作为首轮依赖 |

不默认使用pii-masking-300k：当前许可对商业用途有明确限制。不同版本数据集的许可不能互相套用。公开个人信息数据也不等于企业商业秘密数据。

### 首轮数据预算

1. 冻结敏感类别与保留规则：身份、联系、账号、位置、组织、项目、财务秘密、技术秘密、关联推断风险。区分“实体类型”和“本案例是否敏感”。
2. 先准备1,000～2,000条原创片段跑通；再按许可和质量选择扩展到5,000～10,000条训练记录。
3. 开发集300～500条；保留测试集500～1,000条，另配30～50份完整合成合同/版本对。数量为规划起点，不代表统计充分。
4. 按合同模板家族和来源划分集合；近重复、相同生成模板及双版本合同不得跨训练/测试集泄漏。
5. 加入负例：普通法律词、公开法规名称、经批准保留的金额。加入困难例：跨行账号、别名、页眉、批注、OCR错字、拆分公司名、嵌套地址与多处重复。
6. 通用数据的TIME、DATE、LOCATION等标签按契衡策略映射，不能一律遮盖从而破坏期限和适用法判断。

规则生成样本只算开发材料；由同一规则生成并评分的高分不作为独立有效性证据。模型生成标签须抽检与修正，不能自行充当金标准。

## 6. 识别器如何接入现有技能

拟实现调用链：

```text
原件/案例快照（私有）
  → 本地提取与完整性检查
  → 规则候选＋本地模型候选＋用户词典
  → 原文证据核对、冲突合并、范围策略
  → 确定性替换＋稳定映射
  → 本地复核与版本绑定
  → 私密本地审核；或用户另行批准的脱敏出口
```

模型只输出实体片段、类别、所在片段标识及可核对定位，不直接改写全文。程序检查原文包含关系、重复出现位置、坐标与摘要；不匹配、模糊定位、结构异常或超时均标记待复核。低置信度不当作“安全”；不把模型自报置信分当作校准概率。

候选采取高召回合并。模型不得撤销规则命中；误报通过明确策略或人工裁定解决。重用现有最长优先/非重叠替换，但跨实体冲突保留可审计依据，不能静默吞掉需要复核的候选。

金额/期限敏感且遮盖会影响审核时，本地完成真实数值计算，保留“需本地核算”状态或经批准的关系信息；不编造替代数字。基于文本的识别器不能证明图片、签章或未提取层已脱敏。

### 计划交付的工程产物

- 独立本地模型适配器、模型/词表/量化配置清单；与业务规则解耦，可替换后端。
- 版本化敏感策略、候选与人工裁定契约、失败状态及覆盖记录。
- 本地模型doctor及基准脚本，支持纯合成自检，不回传原文或原始模型输出。
- 数据准备、许可清单、去重/切分、训练配置和一键本地训练脚本。
- 评测报告、错误分类、对照模型选择记录、模型卡及回滚包。
- 接入pipeline及case_store，绑定模型、策略、输入、复核版本；现有版本比较与审核门禁继续生效。
- 仅用于本地打开的复核材料，校验不含外部资源、统计脚本或联网提交。
- 更新大模型Skills入口、安装及隐私说明；默认关闭自动下载、遥测和远端回退。

具体文件名在实现时按已有模块确定；上述是计划，不是已存在的CLI命令。

## 7. 隔离方案：不能只靠Skills提示词

### A. 工程开发与合成实验

可由联网助手在源码工作区编写代码、处理公开许可信息和纯合成数据、安装环境、启动合成训练并读取不含秘密的指标。模型权重下载在接触真实资料前完成，配置本地路径加载和离线运行。

### B. 真实材料私密模式

建议单独的本地标准账户或独立设备环境：该账户不运行联网助手，不向其共享原件目录，不允许助手获得该账户凭证或提权访问。仅建立另一个文件夹、同账号下设置0600权限，不能隔离同账号AI工具。

在要求“不向模型公司提供审核内容”时，真实材料提取、识别、推理、复核、报告全部在本地处理；离线期间关闭Wi-Fi、断开有线及其他网络连接，关闭云同步。操作系统应用防火墙不能当然视为完整出站封锁。长期自动化隔离需选择并实测合适的出站控制及权限方案，不在方案阶段假装已经完成。

加密磁盘/备份、密钥归本人控制；原件、映射、训练权重及适配器均按敏感资产管理。磁盘解锁后，加密不能阻止有权限进程读文件。不能承诺在同一台受管理员或恶意软件控制的电脑上绝对保密。

人工批准出口须由联网助手不能调用的本地流程完成。私密模式默认没有合同内容出口，也不存在“识别通过就自动上传”；可选择仅导出不含文本的计数和运行状态。若未来启用云端审核，须作为独立模式重新授权，保留组合识别和漏检风险说明。

法源材料在联网准备阶段取得并核验版本，离线使用；缺少或过期的来源标明待核实，不能为了检索而自动发送合同原文。全本地法律审核需要另选适合的本地模型与专业评测，不能把1.7B脱敏器视为法律专家。

### 我与用户的执行边界

我可以编写本地脚本、配置、自检程序、回归测试与部署步骤；用纯合成数据验证失败关闭和出口拒绝。权限允许时可协助部署，但安全设置改变必须在具体方案可检查后进行。

真实材料进入强隔离环境后，我不能再通过联网会话读取它们、私有日志、屏幕或模型原始输出。该阶段由用户在本地启动生成好的命令并复核，反馈经检查的指标或错误码。需要持续运行时使用本地任务管理与退出码监控；本计划不代表已安排后台任务，也不承诺对话结束后自动继续。

## 8. 分阶段工作、工时与验收

以一个主要实施者、复用现有技能为前提。工程人时为工作量估算，不代表连续在线服务时间；机器时间可与文档/标注并行，不能简单相加。所有时间在基准阶段后修订。

| 阶段 | 我可执行的工作 | 主要交付/通过条件 | 工程工作量 | 本机运行等待 | 用户参与 |
|---|---|---|---|---|---|
| P0 范围和策略 | 建类别、数据边界、风险假设、验收草案 | 确定仅本地/允许脱敏外发模式，材料范围明确 | 3～5小时 | 无 | 约1～2小时确认业务保密规则 |
| P1 环境与基准 | 独立环境、固定版本、下载核验、1.7B/4B合成试跑 | 确认可运行、内存和吞吐；无真实数据进入 | 5～8小时 | 下载约0.5～3小时；试跑1～3小时 | 约0.5小时，必要安装权限 |
| P2 数据与金标准 | 数据许可记录、原创样本、转换去重、标注工具 | 冻结开发/测试分组，完成标注抽检 | 10～18小时 | 本地生成/整理2～8小时 | 独立复核约12～30小时，可分批 |
| P3 本地识别原型 | 规则/模型融合、定位校验、人工复核、错误关闭 | 跑通合成合同及V1/V2，不改写原文 | 10～16小时 | 基准与测试1～3小时 | 约1～2小时验证使用方式 |
| P4 可选微调 | 100～300步试验、1.7B微调、必要时4B对照 | 保留集确有收益，无明显误遮盖恶化 | 6～10小时 | 合计约6～30小时；慢时缩小试验或重估 | 约1～2小时复核错误类型 |
| P5 私密模式与技能接入 | 独立配置、禁外发自检、案例/报告绑定、回滚 | 对预定边界的读取/网络拒绝测试通过 | 10～18小时 | 自检1～3小时 | 约2～4小时部署账户、断网及密钥步骤 |
| P6 评测与试点交付 | 冻结评测、跨版本回归、操作说明、模型卡 | 阈值达标或明确限制范围；提供回滚 | 8～14小时 | 评测2～6小时 | 专业复核约4～8小时 |

含微调主线：工程工作量约**52～89小时**，本机运行/下载约**14～56小时**，用户及专业复核约**22～50小时**。可并行部分不重复计算为日历天数。若无需微调，省去P4；若标注质量、许可或平台兼容性不达标，时间增加。

### 预计节奏

- **第一周目标**：P0/P1与P2起步，交付公开/合成数据上的基线和原型；不宣称已能安全处理真实合同。
- **第二周目标**：完成领域数据、原型与必要微调；依据实测决定1.7B还是4B。
- **第三至第四周目标**：私密模式部署、独立评测和有限范围试点。
- **稳健预算：3～5周日历时间**，取决于用户复核、可安排机器时段和隔离部署。缩小到合成数据演示可争取3～5个工作日，但不是正式交付标准。

如果另要求“全本地多背景合同法律审核也验收完成”，增加约2～4周工程与试点窗口，并另安排法律盲评；没有专业评审和材料不能承诺该目标在固定日期完成。

### 工程和隐私

- 原文定位、替换后还原一致性、跨版本标记稳定性：验收夹具全部通过。
- 格式错误、输出截断、缺片段、模型不可用、词表不匹配、扫描页缺失：全部进入待复核/阻断，不能返回“无敏感信息”。
- 原件、私有日志、映射不进入未授权工作区；出口拒绝和断网测试有记录，失败即不启用私密模式。
- 统计记录仅含版本、计数、耗时、退出码和不含敏感语义的标识；无内容日志、自动下载、遥测或远端回退。
- 只证明所测配置与范围内的效果，不把合成网络测试宣称为绝对无泄露。

### 识别和审核可用性

- 支持范围内高敏感实体：保留集字符覆盖召回率试点目标≥99%，同时报告实体完整命中率、按类型漏检及置信区间。
- 同时报整份合同残留率，不能只用token准确率掩盖少量高风险漏检。若N份独立合同零残留，仍报告样本量及不确定性；近似95%上界约为3/N，而不是总体零风险。
- 普通实体精确率试点目标≥95%；商业秘密/组合识别单独评测，不并入姓名电话指标粉饰结果。
- 商业秘密定义不清或样本不足时保持强制人工复核，不因总分达标而自动处理。
- 未授权改变金额、期限、单位、否定词和主体关系的确定性回归错误为0；敏感数值被遮盖时标注无法审核的范围。
- 对“未来三年300万/年→未来三年300万”等现有差异场景做回归；处理策略不能隐藏重大修改。

### 何时不继续训练

1. 基础模型＋规则已满足受控试点目标：停止微调，直接做隔离与部署。
2. 1.7B微调收益不足：先检查标注、类别定义和切分，再比较4B；不无限堆训练轮数。
3. 连续两轮受控试验无改善：暂停模型扩容，转向数据修正或缩小范围。
4. 隔离测试失败：仅允许合成数据实验，真实合同保持人工本地处理。
5. 中文子集许可/质量不足：采用原创合成数据与依法授权材料，不用未知来源数据凑数量。

| 训练 | 写配置、启动获授权的实验、保存/恢复检查点、分析非敏感指标 | 私密隔离环境中的本地启动与敏感错误复核 |
| 安全 | 设计边界、写拒绝测试、最小权限配置和回滚步骤 | 账户/密钥/备份控制；不能把凭证交给联网助手 |

| 最终决策 | 给出证据、差距与建议 | 不能替用户批准商业秘密外发，不能替律师做独立法律签核 |

我能承担大部分可脚本化工程工作，但不能自行把生成标签认定为独立专家金标准，不能替第三方授予数据许可，也不能在没有运行证据时保证安全性或法律质量。

## 11. 费用与维护

- 首轮不购硬件、不租云GPU。选用组件目前可按其开放许可使用；不包含可能需要另购的数据授权或专业标注服务。
- 本地计算主要是电费与机器占用。按实际整机功率×小时×当地电价计算，暂不编造固定金额。
- 最大成本是业务标注和错误复核。只选单一或少量合同类型起步，避免第一轮覆盖所有行业。
- 模型/规则/策略/解析库更新均重新跑冻结测试集；先保留当前稳定模型，再原子切换版本。
- 训练权重可能记忆样本，禁止将基于真实合同的权重默认开源或上传。发布前另做数据权利、记忆泄露和许可审查。
- 按用户设定的保留周期清理数据与检查点；不承诺固态盘上普通删除能实现可靠逐文件物理擦除，敏感存储依靠加密和密钥生命周期管理。
