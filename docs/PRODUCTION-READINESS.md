# 生产能力拆解与验收对齐

当前定位：受控、人类复核的合同审查辅助工具。此前7.5/10是工程观察下的主观评分，没有律师金标准支撑，不能作为上线验收分数。

## 服务范围

| 等级 | 使用方式 | 当前结论 |
|---|---|---|
| L1 受控辅助 | 人工核对提取/脱敏，专业人员复核意见 | 可开展试点 |
| L2 有限范围生产 | 限定合同类型、法域、格式、责任人及升级路径，持续监测质量 | 待法律评测、宿主执行及运行验收 |
| L3 独立决策 | 自动确认可签，承担最终法律判断 | 当前不支持；不能以角色数或测试数量证明达成 |

建议先以中国大陆、文字层合同、明确我方立场、专业人员最终裁定为试点范围。扫描件、复杂修订、跨境适用、特殊监管行业分别验收，不能沿用基础场景成绩。这是范围建议，不代表已获得真实合同处理或上线授权。

## 法律质量盲评

1. 冻结类别、法域、日期、我方立场、正文与附件；按合同/模板家族划分开发集和保留集，防止近重复泄漏。
2. 两名独立专业评审先读原件列问题，再查看模型意见；分歧仲裁，保留少数意见与待补事实。
3. 金标准问题绑定原文、触发条件、严重程度和可接受表述。模型意见标支持/部分支持/不支持/待补事实，并记录遗漏问题。
4. 严格支持precision = 支持意见数 / 已裁定模型意见数；部分支持单列。recall = 已匹配金标准问题数 / 金标准问题总数。同一问题重复报告只匹配一次；未裁定项不计通过，并单列覆盖率。
5. 分别报告critical/high漏检率、法源正确率、证据定位正确率、提取缺口率、弃答率、人工修改比例；按合同分组，提供样本量及置信区间。
6. 指标绑定模型、提示词、代码、输入和评审版本。生成模型不得替自己制作独立律师标签。

上线阈值由业务与法律负责人在查看保留集成绩前确定：范围、样本覆盖、允许误报、严重风险漏检上限、人工复核要求、降级及停用条件。本文不虚构通用阈值，也不把未完成评审填成通过。

## 真实执行接口

下一步应适配宿主调度器。在调用边界记录run_id、input_digest、plan_digest、role、round、attempt、宿主任务ID、时间、状态和输出摘要；正文、实体映射、密钥不得进入遥测。

验收：输出绑定具体尝试；失败不计完成；重试不重复计数；输入/计划变化后旧记录不可冒充新执行；R1保持独立；后续轮次可核对收到哪些反馈。模型自行填写的执行JSON仍只算声明。本轮未执行真实六专家四轮审核，后续需原生调用证据。

## 本轮落地

工程验证：`.venv/bin/python scripts/verify.py`。固定pypdf版本、三个独立测试进程、零跳过、合成验收与历史评分数据校验；评测写入临时副本，失败/超时非零退出。按宿主后台日志规范执行。

补审：`pipeline.py report --revision 1`，后续使用`--revision 2`等唯一编号。产物位于`reports/versions/v000001/`：report.md、已验证results.json、manifest.json。清单绑定输入、结果、计划、深度及报告摘要，明确legal_signoff=NOT_ATTESTED；需保留对应版本计划/深度文件。编号仅为标识，不证明新版判断更正确。

版本目录整体提交：审计失败不暴露半成品，修复后同编号可重试；成功编号不可覆盖。原件变化仍须新run，不能仅增加报告编号绕过重新提取/脱敏。旧调用未传revision仍写reports/report.md。

## 推进顺序

1. **工程基线：本轮完成。** 统一验证、版本报告、技能命令对齐。本机51项测试零跳过；CI配置已加入，远端未执行。
2. **宿主执行验收：待实施。** 选定宿主，完成调用记录和恢复适配；用原创合成合同运行真实多专家流程，审核者不接触金标准。
3. **法律盲评：待外部证据。** 确定范围与阈值，取得合法材料及独立专业评审，冻结保留集后评测。缺少材料/评审就保持待验收。
4. **有限范围上线：待前项通过。** 验证隔离、负载、恢复和人工签核；超范围材料转人工，模型/提示词/解析库变化触发复验。

优先补法律质量和真实执行证据；堆角色、轮数或重复合成测试无法替代这些缺口。
