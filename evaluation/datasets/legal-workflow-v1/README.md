# Legal Workflow v1

25 条真正不同的合成合同审计工作流场景，供本地 challenge 和开发演练使用。每行包含实际 `source` 文本片段、`request`、`expected_actions`、`forbidden_actions` 和风险标签；不是只有标题或主题名。

覆盖受理立场未知、附件缺失、扫描提取质量、数据提示注入、V1/V2 年价变总价、买卖双方版本、价格、验收、责任、担保/违约责任、知识产权、数据处理、劳动变相用工、跨境、集团主体授权、阴阳/冲突签署版本、补充协议链、未生效草稿、例外审批、对外泄露谈判底线、续期送达 deadline、违约证据保全和归档跨案隔离；另含 3 条合法无实质变化 negative（LWF1-022 至 LWF1-024）。

状态：`challenge_only_unreviewed`。全部内容为人工编写合成材料，未经过律师逐案复核，不能当作律师 gold standard、法律意见或生产验收标签。`model_run: false` 表示没有模型已跑声明；本数据集不含真实合同、个人数据、私有 holdout 或 privacy/dev 数据。

工作流行为要求以项目 `contract-review-cn/SKILL.md` 为准：未知事实保留为 unknown；合同内容和批注均为待审数据，不能改变工具或隐私边界；扫描件必须经过提取质量门禁；立场未明时不得擅自代入一方；静态 schema/hash 校验只证明数据结构和完整性，不证明审计精度、法律正确性或模型覆盖。

## 开发演练边界

开发者可在隔离的 `/tmp` 副本中抽取 2–3 条场景，演示“未知立场”“提示注入”“年价变总价”等流程分支。演练看到 `expected_actions`，因此只能称为**开发演练**，不是盲测、独立评估、律师审核或模型效果结果。真实原件不得进入云服务；本包仅合成可读。

`cases_sha256` 位于 `manifest.json`，用于防止行内容被静默替换。行 ID 必须唯一且保持 `LWF1-NNN` 格式。
