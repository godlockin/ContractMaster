# 合同审核项目、产品、Skills 与评测集对比

检索日期：2026-09-07。用途：指导 contract-review-cn 后续建设，不构成采购结论。

## 结论与范围

本轮纳入 **17 个项目/产品/插件、5 项评测资源，共 22 个对象**。涵盖中国、以英语法律工作流为主的海外工具、日本背景产品及德国法域研究。不是全球穷尽调查，也不代表各国法律均已覆盖。没有部署第三方项目、购买产品、运行统一横评或完成其安全审计，因此不做准确率排行榜。

可复用实践集中在：企业审查规则、明确的当事人立场、原文证据定位、条款关系、可审阅修订、版本治理、人工升级，以及按任务分开的独立评测。多 agent、多轮、长上下文只是机制，不能直接证明风险发现更好。

证据标记：**源码/指令**＝读过相关公开实现或指令，但不等于运行验证；**文档**＝维护者或供应商说明；**研究**＝论文/数据集说明。短板标记：**已知**＝资料明确显示；**推断**＝根据设计提出的工程风险；**未核实**＝没有足够证据，不能据此认定产品不具备。

## 五、应吸收的实践与应避免的模式

以下是基于上述资料对本项目的设计建议，并非已实现能力，也不是跨产品实测结论。

1. **企业规则有版本、有底线、有责任人。** 每条规则保存适用法域、交易立场、适用条件、首选文本、退让文本、升级条件、审批责任人、生效/复核日期。借鉴 Ironclad、Spellbook、iTerms；避免只有静态风险词表。
2. **法源、企业政策、商业偏好分层。** 法律结论记录官方来源、具体条文、有效期、适用事实及不确定性；企业规则不能包装成法律强制义务。避免美国默认规则、翻译文本或未证实的“行业惯例”直接成为中国法结论。
3. **事实和引用共同定位。** 文档哈希＋版本＋页码/坐标＋字符范围＋原文引句＋关系边。借鉴 OpenContracts、MeCheck；不只保存一段脱离原合同的 AI 总结。
4. **多轮推理输出可核验结论。** 保存问题、证据、适用规则、支持/反对理由摘要、冲突解决、待核实事项。无需输出模型私有思维过程；推理文字长短不能用作质量指标。
5. **修改必须经过上下文回归检查。** 首选最小必要修改，检查定义、金额、责任限制、解除、附件、优先顺序和引用是否同时失效。版本差异用于追踪变化，不用于跳过未改动但受影响条款。
6. **人工升级是产品能力。** 不明确、超权限、缺附件、法源无法确认、专家意见冲突时，输出具体问题及决定需要的材料；不能为了“完成率”强行给出安全结论。
7. **隐私按真实数据路径验收。** 本地解析、自托管、不训练、零留存、加密、访问隔离互不等价。检查 OCR、模型、检索、日志、遥测、缓存、临时文件及备份；不得把原合同文字放进公共搜索查询。
8. **指标按任务拆开。** 抽取、脱敏、检索、上下文推断、风险判断、修改质量各自评测。公开数据集分数不得替代中国合同律师盲审结果。

## 六、当前 skill 的真实位置

| 方面 | 当前已有 | 未解决边界 |
|---|---|---|
| 本地处理 | 提取、可逆 token、映射和文件权限、外发前门禁 | 映射本地明文；规则脱敏可能漏检；没有操作系统级网络/工具隔离 |
| 全文覆盖 | 提取后字符范围、精确引句和完整性校验 | 不能证明 PDF 图片、扫描页、布局全部被正确提取；字符入账不等于理解正确 |
| 多角色多轮 | 六角色、四轮记录、条款关系及多跳覆盖契约 | 声明完整不等于实际推理完整；缺六角色四轮端到端法律质量验收 |
| 法律及信息安全 | 法域适用矩阵、规范类别、安全控制、未决事项门禁 | 不是所有法律法规数据库；缺持续验证的法源版本库和律师维护机制 |
| 输出 | 可定位 Markdown 风险、建议、覆盖记录 | 缺经过版面验收的 DOCX 修订、跨版本回归和企业规则治理 |
| 测试 | 合成样本、确定性校验、单 agent 初步盲测 | 旧 14/14 试测不是律师金标准，不是新四轮协议验收，不代表生产通过 |

本项目的实现组合包括本地映射、发布门禁、字符覆盖和多轮证据契约；可以称为本项目自行实现，不能宣称这些思想在全球独有。代码来源说明见前述中国项目溯源。

## 七、建设优先级与验收要求

这是后续实施方案，本轮未据此改动执行代码。

| 优先级 | 建设项 | 可验收结果 |
|---|---|---|
| P0 | 法域/日期/立场/行业事实确认；法源与企业政策分层 | 适用依据缺失时显示未核实；所有法律结论有可打开的来源、条文和版本记录；失效法条不能无提示进入最终结论 |
| P0 | 企业 playbook 单一来源与版本 | 每条有条件、底线、负责人和版本；版本变动可追溯到受影响审查结果；偏好不误标为违法 |
| P0 | 提取及脱敏失败门禁 | 扫描页、表格、页眉脚注、附件缺失都有测试；逐页核验；已标注敏感实体漏出测试必须失败；门禁通过不宣传零漏检 |
| P0 | 独立中国法验收集 | 开发样本与留出集隔离；至少两名具备相关背景的审阅者独立标注并仲裁；记录分歧、法源、漏报/误报、严重性和不确定性；质量阈值在测试前约定 |
| P1 | 原文坐标与 DOCX 修订 | 每项能回到原文；修订后渲染检查；定义、金额、交叉引用和责任条款无意外破坏 |
| P1 | 主合同—附件—补充协议关系及改动传播 | 明示关联与隐含依赖分别记录；跨文档优先顺序、例外、冲突、循环引用均有独立样本 |
| P1 | 多专家/多轮增益实测 | 同一留出集比较单角色、六角色一轮、六角色四轮；固定模型/预算条件并报告成本差异、漏报、误报和耗时。保留用户要求的全文、多轮模式，未经证据不声称更多轮必然更好 |
| P1 | 工具及出站边界 | 非法文件读取、恶意合同指令、带原文的网络请求、映射误入日志均有执行级测试；失败时阻断，不只检查模型报告是否声称安全 |
| P2 | 宿主、模型、解析器适配层 | 能力探测；不支持并行/OCR/联网核实则明确降级与遗漏；换模型后重新验收，不以“兼容 API”替代质量验证 |
| P2 | 运营与成本 | 保存版本、法源核实时间、阶段状态和消耗；日志不含原文和映射；支持失败恢复，避免重复外发 |
