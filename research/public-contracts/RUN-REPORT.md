# 体系升级与公开合同试审交付

日期：2026-09-07。

## 人类专家从这里开始

打开 [离线复核台](human-review/index.html)。每份合同可查看原始PDF、审核所用文本、AI意见、引文及独立质询；逐项选择支持/部分支持/不支持/待补事实，填写修正意见，再导出JSON。刷新前需要导出，本页不自动保存，也不向外部服务提交。

也可使用 [CSV裁定表](human-review/adjudication-template.csv)。CSV包括原始AI意见、交叉质询及空白人工裁定栏；本轮没有替人类专家填写结论。

建议两位专家先各自阅读原件，再看AI意见，独立导出裁定。另记录AI没有提出的遗漏、原件提取错误及需要补充的事实；不能只评价已有65项的正确性就声称测出召回率。

## 本轮发现的具体问题

- 工程合同初评部分意见忽略已有救济、混淆配置提醒与确定缺陷；复核台并列显示反证和修改意见，让人类专家判断。
- 服务模板仍引用《合同法》；按新签或历史交易区分处理，不能从引用过时直接推断合同无效。相关试审保存核验链接。
- 技术汇编中的沉默变更、研发失败结算、既有许可及后续改进等需要按模板分别判断；没有把未知法源标成已核验。
- PDF水印会造成重复文字、姓名识别漏检，公式也可能提取失真。修正了识别到的公开水印姓名，记录公式/版面缺口，未把提取错误当作已证实原文缺陷。

## 技能升级

新增交易画像、审核角度责任矩阵、动态专家组队、初始化及工具就绪阶段。六基础角色保留，专项角色按合同事实增派；每个新增角色仍要求全文和四轮覆盖。

执行结果绑定当前专家计划的摘要及版本；显式激活新计划后，旧计划结果不能回退充当当前完成结果。缺工具、未知范围、未核验法源、未解决问题、动态领域遗漏保持部分审核。

独立代码审查发现并修复四类门禁漏洞：JSON转义造成敏感值漏检、计划与深度范围不一致、实际风险中的未决项未联动、旧计划重放。状态声明仍只是结构与记录验证，不能证明模型认知、法律正确性或OS隔离。
